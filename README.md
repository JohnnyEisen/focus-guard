# FocusGuard 聚焦护栏

> AI 履职执法模型 v3.0 + 动态预算 + 卷宗体系 + 正面指引（v2.2.0）—— 一个让 AI 智能体"依法履职"的全自动 ZCode 插件。

FocusGuard 是给 AI 编码智能体（**ZCode 与 DSH 双端原生硬拦截**，兼容 Claude Code 钩子协议）装上的一套**纪律与监察系统**：日常对话零打扰，一旦出现"未取证就改代码、结论无证据锚点、整读大文件烧上下文、无限空转"等失控行为，立即按梯度处罚——打回重写、强制取证、熔断锁定、记档、降权、上报人类。所有执法行为全程留痕，接受人类随时复核。

## 为什么需要它

AI 智能体最常见的三种失控：

1. **思考失控**：没有证据就开猜，越查越偏，停不下来；
2. **资源失控**：整读大文件、未过滤刷屏，上下文和 token 被无意义输出撑爆；
3. **权限失控**：拿不准也硬改，先斩后奏，出了问题无法追溯。

FocusGuard 用"立法 → 执法 → 监察"三件套把这三类失控变成**机械可拦截**的行为事件，而不是靠提示词里的一句"请不要乱来"。

## 核心机制

### 空气层（日常零打扰）
对话、分析、讨论、解释：不查、不拦、不提醒。执法只看行为，不查词。

### 触发层（行为五条，违规即罚）
| # | 触发条件 | 说明 |
|---|---|---|
| ① | 未取证就改 | 本回合 0 次调查（读文件/Grep/搜索/只读命令）就 Write/Edit/改动类 Bash |
| ② | 无锚点结论 | 回合内调用 ≥5 次后收尾无 `[文件:行号]`/`[日志原文]`/工具结果，也未标【假设】 |
| ③ | 体积刺客 | 整读 >50KB 文件、Grep content 无 head_limit、裸 cat/type 刷屏 |
| ④ | 动态预算超限 | 有效调用超任务预算，或连续 3 次无效调用（真失控） |
| ⑤ | 硬凑不熔断 | 查无实据仍强行猜测，不申报熔断 |

### 梯度处罚（L1-L6）
`L1 打回重写 → L2 强制取证 → L3 熔断 → L4 记档 → L5 降权 → L6 上报人类`
同回合违观数累加自动爬升；熔断期只读调查类工具仍可使用，改动类全拒；人类一条新指令即"批示"，全部解除。

### 动态预算 + 进度检测
- 任务预算按批示关键词自动设定（重构/全量类 50、修复类 15、其他 10），首轮可声明【任务规模】上调；
- **双预算池**：侦查（只读）与执行（Write/Edit/变更命令）分池计数，互不挤占；侦查池独立 15 次，超限提醒收敛，短指令『追加额度』双池+10；
- **有效调用**（返回内容有变化/产生文件变更/出现新报错）满阈值自动续杯 +10，硬上限 200；
- **无效调用**（重复读同一内容/同命令同返回）连续 3 次 → 判定真失控直接熔断；停滞 2 次可申请【信用延期】由人类批示。

### 卷宗体系（v2.0，总纲见 `docs/MASTER-PLAN-2.0.0.md`）
工作区档案 `<工作区>/.ai/CASE_FILE.md` 四册：

| 册 | 内容 | 维护方 |
|---|---|---|
| 【一】环境声明 | OS / Shell 版本 / 编码 / 路径分隔符 / 大小写敏感 / BSD 工具 / 可用命令 | 引擎（会话级一次检测） |
| 【二】项目依赖声明 | 依赖名/版本/安装路径/信任TTL（如游戏本体 60 天） | **人工填写** |
| 【三】侦查取证记录 | 文件名/读取时间/mtime/size/SHA-256/变更历史/TTL/验证方式 | 引擎自动追加 |
| 【四】工作额度台账 | 初始额度/已用/剩余/有效/无效调用 | 引擎（回合末落卷） |

- **环境检测一次全程复用**：SessionStart 检测一次写入 `state.envCache`，UserPromptSubmit 不重检，仅当探测到 shell 变化时重检；
- **跨回合取证指纹**：mtime + size + SHA-256（≤200KB）+ git 脏态四层校验，指纹一致且 TTL 未超 → **免重读放行**（拦截本次 Read，复用已有取证）；指纹不一致或 TTL 超时 → 放行真重读并更新卷宗。时间戳伪造（`touch -d`/`cp -p`/`git checkout`）无法绕过 SHA 内容校验；
- **自适应 TTL**：首次 4 小时 → 7 天内有变 2 小时 → 7-30 天未变 24 小时 → 30 天未变 7 天；优先级：**依赖声明 > 人工标注（【三】TTL 列手填）> 自适应**；
- **免重读豁免**：offset 增量读永远放行；熔断/强制取证期豁免（降级重建证据需要真重读）；
- **跨平台命令拦截**（按检出 shell 适配）：PowerShell 会话禁 bash 管道（`\| head`/`&&` 等）与裸 Get-Content，改用 `Select-String`/`Measure-Object`/`-TotalCount`；macOS 禁 `sed -i` 无后缀、`grep -P`、`readlink -f`；大小写不敏感文件系统禁仅大小写不同的重名文件；Linux 标准 GNU 无特殊限制。

### 监察与留痕
- 盲写拦截：写"本回合没读过的已存在文件"100% 拦截；
- 风险文件（`package.json`、lock、CI 配置等）修改 100% 留痕；
- 上下文污染检测：工具输出与指令矛盾（head 行数超限 / 清单路径重复）→ 立即停用该输出，用带标记小命令隔离核实并报告人类；
- 回合卫生：回合开始核验上一回合状态残留（43条），异常记档后清理；新会话检测到 HANDOFF.md 注入交叉巡视提醒（36条）；引擎与工作区源码版本不一致告警（42条）；
- 一切执法行为（触发/处罚/抽查/特赦/预算伸缩）写入 `<工作区>/.focus-guard/AUDIT.log`（JSONL），字段：时间/会话/动作/触发条件/级别/证据/是否特赦。

### 正面指引（v2.2.0：告诉 AI 怎么干活，而不是只知道不能干什么）
负面清单管下限，正面指引给标准动作（法条第十五章之一，74-79 条；运行时镜像见 `focus-thinking` 技能 §10）：

| 树杈 | 标准动作 | 机械化 |
|---|---|---|
| 环境适配 | 环境不主动探测，行为暴露后自动适配；有 .git 用 `git restore` 回滚，没有用 `.ai/backup/` | 引擎在每次 Write/Edit 前自动备份到 `.ai/backup/`（保留最近 100 份） |
| 返工与提交 | 只回滚出错文件；重试带"失败包裹"（报错行号+堆栈尾 30 行+限定范围）；本地 commit 测试全绿 AI 可做 | **推送闸**：`git push` 一律拦截，推送由人类在 UI 执行（当回合短指令特赦放行，`--dry-run` 例外） |
| 污染与日志 | 参数-输出矛盾 → 标记可疑；改文件前先输出【污染核实】声明；超大日志只取统计+堆栈尾 30 行 | **污染核实闸**：污染检出后首个改动类先拦一次 |
| 任务编排 | 第一句话声明"通过条件"（可测=测试退出码 0；不可测=编译+不崩溃+《人类验收清单》）；机械任务优先内置库与 `.ai/tools/` 预制脚本 | 结案以机器退出码为准 |
| 人类交互 | 提交前固定一行：【提交申请】修改:\<文件\> (+n,-m) \| 测试:n/n 绿 \| 允许提交？(y/n)；仅不可逆操作请示 | 其余全自动 |
| 经验固化 | L2/L3 或回滚后往 `.ai/PATTERNS.md` 追加 `[环境:x] [任务:y] 以后遇到X必须先做Y`；新任务不预读，卡点时 Grep 检索 | 熔断出口提示经验固化 |

### 子代理委派（v2.3.0：把子代理变成高产出、低污染的标配）
| 机制 | 规则 | 机械化 |
|---|---|---|
| 委托池独立核算 | 默认 20 次/任务，不占执行池；用尽批示『追加委托额度』+10 | 每次委派记 `delegate-used`；用尽拒绝并请示 |
| 摘要强制格式 | 主会话只收【子代理摘要】四字段（任务/结果/异常/文件线索），≤200字 | 超长或缺字段 → 拒收要求压缩（KPI-3） |
| 强制委派场景 | 全库搜索≥3目录或≥10文件 / 大文档>50KB或>2000行 / 批量≥5文件 / 独立并行 | 未委派 → 未尽职提醒（KPI-5）；已委派 +5 |
| 合法委派边界 | 正常委派放行不计违规；仅熔断期启动子代理=越权绕行（L4+L5） | 消除"不敢委派"，KPI：+5/+3/-5/-3 |

### Token 预算（v2.3.0 实测，`node tests/token-bench.mjs`）
拦截报文与常驻注入全部进模型上下文，按电报体压缩后实测（1 token≈1.5 中文字符）：

| 事件 | 优化前 | 优化后 | 节省 |
|---|---|---|---|
| SessionStart 常驻注入 ×1 | 578 字 | 489 字 | -15% |
| 卷宗免重读 ×10（最高频） | 196 字/次 | 144 字/次 | -27% |
| 触发③体积三闸 ×3 | 412 字 | 277 字 | -33% |
| 熔断出口（拒绝+打回） | 622 字 | 268 字 | -57% |
| 推送闸拦截 | 146 字 | 64 字 | -56% |
| **典型会话加权合计** | **4737 字** | **3240 字** | **-31.6%** |

即典型会话执法可见开销 ≈3158 → ≈2160 tokens（约省 1000 tokens/会话，区间 750~1250）。报文只保留"标签+动作指令"，规则细节由 focus-thinking 技能与 docs/RULES.md 承载。

### 高危命令闸（v2.4.0：99% 自由 + 1% 单行审批）
即使完全访问（yolo/自动批准）模式，**六类不可逆命令仍须实时审批**：破坏性删除（rm -r、shutil.rmtree、DROP TABLE、TRUNCATE）、强制推送与历史覆盖（**git push**、git reset --hard、git clean -fd）、系统权限与配置（chmod 777、chown、reg add/delete、net user）、全局依赖安装（npm install -g、apt-get install、docker run --privileged）、对外发送与发布（npm publish、docker push、curl -X POST）、数据库影响（无 where 的 DELETE/UPDATE）。

- **审批单（唯一通道）**：命中 → 拒绝并要求一行【高危申请】命令：`<真实命令>` | 真实目的 | 影响范围 | 回滚方案 | 允许执行？(y/n)；收尾没带单 → Stop 打回补交。
- **y 放行本次**（一次性，再跑重新批）；**n 彻底阻断**（会话内不得重发）；逐字一致校验——人类批的就是会跑的那条。
- **预授权隔离**：任务指令里的「最后上传github」只是目标预授权（goal），不解锁执行；执行级授权只认人类当下对审批单的短批示。
- **严禁脚本包装**：被拒后写 push.sh 再跑 = 对抗审查 L4；写高危脚本本身也要走审批单。
- **不设卡**：普通单文件 rm、构建、测试、本地 commit。放松日常 + 刚性高危。
- **v2.4.1 特征库加固（极限场景测试产出）**：堵住 `git -C <目录> push` 传参绕行、`rm --recursive` 长旗标绕行、node `rmSync(recursive)` 绕行、无 where 的 DELETE FROM/UPDATE SET（带 where 自由）；post 阶段五处响应采样合并为单次（CPU 减负）；卷宗缓存 200 条上限裁剪；50/52→57 用例含 80KB 命令行、2MB 响应、损坏状态、奇异会话 ID、中文路径等极限用例。

## 安装

逐行可复制的安装命令、DSH 工作区（CS2 modding / C#）部署与 FAQ 见 **[INSTALL.md](INSTALL.md)**。概要：

### 方式一：ZCode 插件市场（推荐）
1. 克隆本仓库到本地任意目录；
2. ZCode → 插件市场 → 添加 → 添加插件市场，选择仓库内 `marketplace.json` 所在目录（或直接选择本仓库目录）；
3. 个人 → FocusGuard 聚焦护栏 → 安装。

### 方式二：手动注册钩子
将 `hooks/hooks.json` 中的六条钩子按 ZCode 钩子规范注册到你的配置中，命令指向 `hooks/guard.mjs`。

要求：Node.js ≥ 18（仅使用内置模块，零依赖）。

## 工作原理

```
SessionStart       → 环境检测一次 + 卷宗载入（重建取证缓存与 TTL 表）+ 注入执法模型
UserPromptSubmit   → 批示识别（关键词预算/信用延期/特赦/追加额度）+ 重置任务态（保留侦查缓存）+ shell 变化重检
PreToolUse         → 平台命令拦截 + 推送闸 + 熔断白名单 + 未取证拦截 + 污染核实闸 + 体积三闸 + 盲写拦截 + 卷宗免重读 + 改动前备份
PostToolUse        → 进度检测引擎（双预算池/续杯/停滞熔断）+ 卷宗取证记录 + 污染检测 + 抽查
PostToolUseFailure → 失败计入停滞
Stop               → 回合边界 + 证据锚点检查 + 授权识别核验 + 额度台账落卷
```

所有拦截通过钩子标准协议生效：PreToolUse 退出码 2 拒绝工具调用，Stop/PostToolUse 返回 `{"decision":"block","reason":...}` 打回重写。

## 设计取舍与已知边界

- **回合边界双保险**：实测 `UserPromptSubmit` 钩子不保证触发，故回合计数由可靠的 `Stop` 事件兜底清零，`reset` 仅作尽力而为的提前重置；
- **钩子读取的是安装副本**：修改源码后需同步到插件安装缓存（或经市场更新）才会生效；
- **平台受限暂缓条款**：第21条 Token 成本核算、第37条思考链监管（钩子层不可见 token 用量与思考时长）、第64条(二)(三)(四)限流（无对应信号）；第48条子代理继承以留痕方式实现（平台无状态注入通道）；
- **免重读的边界**：卷宗指纹一致但会话上下文已被压缩时，用 offset 增量读或请批示；【二】依赖声明与【三】TTL 列人工标注可按需放宽/收紧；
- 违禁词扫描已废弃（v3.0 起"不查词"）：空气层允许口语与主观语气，执法只看行为。
